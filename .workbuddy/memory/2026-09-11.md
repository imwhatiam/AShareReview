## 前端指向本地后端服务的配置方式

- 前端**不存在 `VITE_API_BASE_URL` 之类的基址变量**：`src/api/client.js` 只发相对路径（`/api/...`）且 `credentials: 'same-origin'`，所以开发期完全依赖 Vite dev server 代理。
- 唯一开关是仓库根目录 `.env` 的 `VITE_DEV_BACKEND_ORIGIN`：`vite.config.js` 用 `loadEnv(mode, '..', '')` + `envDir: '..'` 读取，交给 `src/api/developmentProxy.js` 的 `createDevelopmentApiProxy()` 生成 `{'/api': {target, changeOrigin: true}}`。该文件为空/空白时返回 `{}`（不代理）。
- 本次把 `VITE_DEV_BACKEND_ORIGIN` 从 `http://127.0.0.1:8000` 改成 `http://127.0.0.1:8765`。**写 `127.0.0.1` 而非 `0.0.0.0`**：`0.0.0.0` 是监听地址，做代理 target 在部分环境下不稳定，等价于本机回环。
- 改完必须重启 `npm run dev`（envDir 在项目根之外，改动后 vite 不一定自动重启配置）。
- `frontend/src/viteProxyConfig.test.js` 断言的是函数行为（用 8000 举例），与 `.env` 实际值无关，无需同步修改。
- 生产构建是静态产物、同样只发相对 `/api`，因此不需要基址变量，而是要求**同源反代**（Django 直接托管或 nginx）。若真要跨源部署，得改 client.js 加 base URL，并同步 `.env` 的 `CORS_ALLOWED_ORIGINS` / `CSRF_TRUSTED_ORIGINS` 与 cookie `SameSite`/`Secure`。

## 排查：`--latest` 抓到 270 条数据，页面却显示「暂无数据」

**现象**：`python manage.py fetch_kaipanla_sector_fund_flow --latest` 在 17:48 执行成功（"published 270 records"），`kaipanla.sqlite3` 也确实写入 270 行、`DataVersion` 有 `business_date=2026-09-11` 的 complete 版本，但前端打开资金流页仍是空（`series: []`，非 404）。

**根因：上游 `Time` 字段盘后返回的是「当前时刻」，而读路径只认标准交易槽。**
1. `fetcher._source_metadata` 取上游响应的 `Time` 作为 `source_timestamp`；命令 `--latest` 的 `_snapshot_time` 直接用 `datetime.fromtimestamp(ts, Shanghai)` 对齐 5 分钟。盘后（17:48）执行时上游给的是**当前时间**，于是快照时间 = 北京 17:45。
2. `trading_slots_for_day()` 只生成北京 09:30–15:00 的 50 个标准槽（存库即 UTC 01:30–07:00）；`load_intraday_snapshot_rows` 用 `snapshot_time__in=time_axis` **精确匹配** → 北京 17:45 不在其中 → 0 行。
3. `_build_series` 找不到落在时间轴上的快照 → `query_intraday` 返回 `time_points: []`、`series: []` → 前端判定「暂无数据」（`KaipanlaPage` 的 `date` 初始值是 `''`，即不带 date 请求，后端 `_published_version(None)` 选 `order_by('-business_date')` 最新的 09-11 这条坏数据）。

**对照证据**：库里 09-09 那条快照是 UTC `05:55`（= 北京 13:55），落在交易时段内，所以 `query_intraday(2026-09-09)` 正常返回 4 条 series。

**⚠️ 时区陷阱（以后直读 sqlite 必须记得）**：`TIME_ZONE=Asia/Shanghai` + `USE_TZ=True`，Django 的 `DateTimeField` 在 sqlite 里存的是 **UTC**。所以直读看到的 `2026-09-11 09:45:00` 是 UTC，换算北京时间要 **+8h = 17:45**。验证技巧：`trading_slots_for_day(d).astimezone(ZoneInfo('UTC'))` 打印出存库时的期望值再比对。

**测试盲区**：`test_command.py` 的 `source_timestamp=int(self.snapshot_time.timestamp())` 用的是 2026-09-08 **10:05（交易时段内）**，因此没覆盖盘后执行的情形，缺陷才会溜过。

**影响面**：多日模式的 `load_close_snapshot_rows` 只取 **15:00** 快照，今天的 17:45 行同样取不到，所以 5/10/20 日窗口也会缺当天。

## 日期控件改自绘：替换原生 input[type=date] 的日历弹层

**需求**：「点击日期，弹出的日期选择框太丑了，更新下使符合整体 UI 风格」。

**为什么必须重写而不是改样式**：用户看到的弹层是**浏览器原生 `input[type=date]` 的日历**，它渲染在 UA shadow DOM 里，页面 CSS 完全够不到（`::-webkit-calendar-picker-indicator` 只能改触发图标，`::-webkit-datetime-edit-*` 只能改框内文本，弹层本体无任何可用钩子）。`color-scheme` 也只影响明暗，改不了品牌色与圆角阴影。→ **只能自绘**。

**实现**：
- 新增 `src/shared/ui/DatePicker.jsx`（删除 `DateField.jsx`，4 个调用点改 import：`FlowControls` / `StockMovesPage` / `SectorMomentumPage` / `HundredDayPage`）。用 `DatePicker` 命名是因为它不再是"原生日期 field"。
- 触发器是 `<button aria-label="数据日期" aria-haspopup="dialog" aria-expanded>`，沿用 `.field__input` 的边框 / 圆角 / 内边距 / 字号；弹层 `role="dialog"`，头部 `« ‹ 年/月 › »`，7 列网格，底部「今天 / 最新交易日」（后者等于 `onChange('')`，与"空值 = 最近交易日"语义闭环）。
- **可访问名继续挂在触发器上（`aria-label="数据日期"`）**，所以 `getByLabelText('数据日期')` 与 AppShell/KaipanlaPage 里的 `toBeInTheDocument()` 断言一行没改。
- 键盘：roving tabindex（只有 `focusDay` 那格 `tabIndex=0`），方向键 ±1/±7 可跨月，Enter 选中，Esc 关闭并回焦，点击外部关闭。
- 选中态用 `aria-current="date"`（不是 `aria-pressed`——日期选择不是 toggle）；"今天"用 `.is-today::after` 底部小圆点弱提示。

**⚠️ 弹层必须用 `position: fixed`（或 portal）**：祖先 `.panel` 带 `overflow: hidden`（`index.css:298`），`position: absolute` 的弹层会被裁掉。**fixed 的包含块是 viewport，不受祖先 overflow 影响**——但前提是祖先链上不能有 `transform` / `filter` / `backdrop-filter` / `will-change` 创建 containing block。本项目唯一的 `backdrop-filter` 在 `.app__nav`（header）上，不是 `.app__main` 的祖先，所以 fixed 安全。朝上展开时用 `bottom` 定位（而非算 top），弹层高度变化不会错位。

**测试策略（关键取舍）**：原生 input 被移除后，`fireEvent.change(input, {target:{value}})` + `toHaveValue` 全部失效。新增 `src/test/datePicker.js` 导出 `pickDate(target)`：打开弹层 → **按月份标题导航到目标月** → 点 `aria-label="<ISO>"` 的格子。**必须做月份导航**：弹层默认停在 value 所在月（value 为空时是"今天"所在月），写死"直接点 9 月 8 日"的测试会随运行日期漂移而挂。断言侧把 `.toHaveValue(...)` 换成 `.toHaveTextContent(...)`（读触发器文本）。
- 新增 `DatePicker.test.jsx` 7 条：占位文案、弹层月份、选日期回调、方向键跨月、年月导航、Esc / 外部点击关闭、清空回最新。
- **前端 59 测试全通过**（52 → 59）、lint 无告警、build 成功。

**视觉验证**：探针读到弹层 `{width: 272, height: 299, top: 93, left: 102}` 在视口内；**用 `getBoundingClientRect()` 量化网格对齐**（肉眼在图上看不清是否被裁）：7 个表头 left = 115/150/185/221/256/292/327（间距 35–36px 完全均匀），第一行日期 left 顺序 `185,221,256,292,327,115,150` 正好对应"9/1 是周二、前两格留空"，`grid.right=361` 而弹层内容右边界 362 未溢出错。窄屏用 iframe(390px) 验证：触发器撑满整行、弹层完整落在视口内。

**⚠️ 估算高度要按"最大行数"取**：`POPOVER_ESTIMATED_HEIGHT = 336` 是为 6 行月份的弹层预留的翻转判断基准（实测 5 行月份为 299px）。取实际值会让 6 行月份在下方空间临界时"该翻转却不翻转"。

**新增第 5 条视觉验证经验**：判断"网格列是否被裁/是否均匀"这类问题，**不要靠肉眼看截图**（图表线穿过弹层会严重干扰判断），在页面里注入 `getBoundingClientRect()` 测量并把数组写进 `#probe` 用 `--dump-dom` 读出来。

## 资金流页三项图表/控件调整

**需求**：① 去掉「当日/5日/10日/20日」分段控件的背景边框，并与左侧日期控件上下对齐；② 分时横轴刻度改为整十分钟（下午 13:00 起、末刻度 15:00）；③ 折线图去掉顶部图例，改为每条折线右端常显"板块名 + 资金净额"。

**① 分段控件**（`index.css` 的 `.segmented`）：删掉外层 `border` + `background` + `padding`（原为 `--color-surface-muted` 灰底 + `--color-border` 边框的胶囊盒），`.segmented__item` 纵向内边距从 `0.3125rem` 改为 `0.4rem` —— **与 `.date-picker__trigger` / `.field__input` 完全一致**（0.4rem + 1px 边框 + `var(--text-base)`），因此 `.toolbar { align-items: flex-end }` 下两者上下边缘齐平。实测截图：日期框与激活胶囊同为 y=45→81，误差 0。激活态保留 `--color-brand-50` 浅蓝底 + `--color-brand-700` 文字（`box-shadow` 去掉）—— 外层盒子没了之后，白底白胶囊会看不见选中项。

**② 横轴刻度**（`chartTheme.js` 新增 `isClockTick` + `clockCategoryAxis`）：
- **根因**：原来走 ECharts 默认的按索引等间隔抽稀。上午 09:30–11:30 是 25 个槽（奇数），步长 2 跨过午休后错位一格 → 下午首个刻度 13:05、末刻度 14:55。用户报的"不要从13:05开始"正是这个。
- **修法**：`axisLabel.interval = (index, value) => isClockTick(value)`，即只保留**分钟数为 10 的整数倍**的时刻 → 09:30…11:30 / 13:00…15:00 共 26 个刻度。必须 `hideOverlap: false`：午休两侧的 11:30 与 13:00 在类目轴上相邻，交给 ECharts 防重叠抽稀会把 13:00 丢掉。
- **`option.xAxis.data` 仍保留原始 timePoints**（测试直接断言）；`IntradayChart` 传 `timeAxis: true` 走新轴，多日图继续用 `categoryAxis`。
- 副作用：`11:30` 与 `13:00` 两个标签在午休处紧贴（类目轴把 90 分钟午休压成相邻两格）。用户未提，未处理。

**③ 线端标签**（`chartTheme.js` 的 `flowLineSeries` / `flowOption`）：删掉 `legend`，每条 series 加 `endLabel`（`formatter` 输出 `板块名 +34.7亿`，正数带 `+`，一位小数，颜色随资金方向红/绿）+ `labelLayout: { moveOverlap: 'shiftY' }`；`grid` 改为 `{ top: 36, right: 132 }`（132 是给"光伏设备 +34.7亿"这类文案留的横向空间；`top` 从 56 降到 36 但仍要够 y 轴名称 —— 一开始设 20 把 `累计净额（亿）` 裁掉了）。新增导出 `formatFlowAmount()` 供测试复用。

**⚠️ `moveOverlap: 'shiftY'` 的最小行距锁死在字号（11px）**，给 `endLabel` 加 `padding: [3,0]` **无效**（实测间隔仍是 11）—— ECharts 的 label 布局不用 padding 撑盒。10 条线在右端收敛时标签会紧贴但**不重叠**，可读；已接受，未再折腾。

**验证手法（本次新收获，比截图更快更硬）**：**用 ECharts 的 SSR SVG 渲染在 Node 里直接验证 option 的绘制结果**，不依赖浏览器：
```js

chart.setOption(flowOption({...}))
const svg = chart.renderToSVGString()   // 正则抽 <text> 文本 / transform="translate(x y)" 量间距
```
