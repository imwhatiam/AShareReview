## 第五轮：crontab 标记常量改名（用户点名"要一并改名"）

上一轮我判断 crontab 标记串是"改名会让已安装块删不掉"的例外，用户明确要求改。**正确做法不是保留旧串，而是让清理逻辑按形状匹配** —— 这样既去掉了项目名，又不用把旧串字面值抄回源码，且已安装的旧块仍能被清掉。

用 `tests/bin/crontab` 替身（通过 `PATH` 前置拦截 `crontab -l` / `crontab -`，读写重定向到文件）跑了 **6 组用例** 18 条断言：识别旧块并删除、install 先清旧块再写新块、重复 install 不叠加、install→uninstall 归零、无块时 uninstall 不动用户条目、空 crontab 时 install 正常。全绿后做**变异验证**：把模式改成只认新字面值 → 同一套用例 **6 条失败**，证明断言有牙。探针已删，`tests/` 只剩 `.gitkeep`。

### 本轮踩的两个坑（写进 `test-assertion-discipline` 技能）

1. **替身与真实实现的语义差会造成假通过**：第一版替身用 `cat > "$store"` 直接写，而脚本是 `crontab -l | awk | crontab -` 的管道 —— 写端把读端正读着的同一个文件截断了，结果"用户条目凭空消失"，同时让"块已清除"这类断言**假通过**（因为整份文件都没了）。改成 `mktemp` + `mv` 原子替换后，读端读完才发生替换，无竞态。

### 一个通用的 gitignore 语义坑（本轮又验证一次）
