# 文档组织约定（专题）

## 目录结构

- **仓库根只留 `README.md`**（+ `AGENTS.md`，被 IDE 自动加载，**不能**移进 `docs/`）。
- 其余文档全在 `docs/` 下，**只有 4 个子目录 5 篇**：`specs/integration-spec.md`、`acceptance/traceability.md`、`data-sources/web-api.md`、`ops/deployment.md`、`ops/manage-commands.md`。
- **不设** `docs/ideas/`（构想属于规格 §1 背景）、`docs/reviews/`（审查结论属于 `AGENTS.md` 与技能）、根目录的 `tasks/`（实施计划不进仓库）。
- 上游数据源边界不是独立文件，是 **`docs/data-sources/web-api.md` §6**。

## 内容边界

- **README 是总览，不是规范**：§2/§3/§4 顶部各有一句「本节是总览，规范性契约以规格/命令手册为准」的指针。大块配置（Nginx / gunicorn / systemd / crontab）**一律不在 README**，只在 `ops/` 里写一份。
- 细节文档由 README 链接，**不重复同一份内容**。`web-api.md` §6 与 `AGENTS.md` 的数据源边界**有意保留少量重叠**（AGENTS 被 IDE 自动加载、必须自带约束；§6 是接口侧的完整版）。
- **写文档前先 grep 字面量，不要凭印象写枚举**：例如响应外壳的 `source` 只有 `cache` / `database` / `computed` 三个值，文档里写成四个值就是错的。

## 去历史化规则

**文档只描述当前状态，不写版本号、日期、已删除概念、变更叙事。** 读者只需要知道"现在有什么"，不需要知道"曾经是什么"。

**要删**：日期与版本号（`2026-09-08`、`1.11.0`）、已删除功能/命令/表/配置键的提及（**含"否定式提及"**，如「`.env` 里没有 `REMOTE_REPAIR_*`」）、变更叙事（原先 / 已删除 / 不再存在 / 取代 / 旧机器升级提示）、写作期的流程产物（评审闸门、待确认清单）。

**不删**（这些是"当前语义"或"当前事实"，删了反而错）：

- `旧数据` / `旧缓存` / `旧快照` / `旧版本` —— 指 **stale 回退**这条现行行为。
- `历史行情` / `历史日线` / `历史缺失填 0` —— 现行算法口径。
- `旧口径` / `旧键不再命中` —— 现行缓存身份机制。
- **支撑当前配置取值的实测数字**（页面宽度预算、上游分页上限、全市场股票数）—— 这是"当前事实的验证"，不是"过去的状态"。
- 上游的当前状态（开盘啦 881 族对北交所仍用旧代码）。

**教训**：纯词频扫描会严重高估（`旧数据`、`历史` 绝大多数是现行语义）。做法是先用**强标记正则**（日期、`已删除`、`原先`、`不再存在`、`本轮`、`实现前`、`就地改写`、`历史说明`、`旧机器`）抽行，再逐行判断。

**判断标准：这句话对"现在该怎么用"有没有信息量？没有就是在讲历史。** 否定式提及尤其容易漏 —— 写完一定要跑一遍"必须消失"令牌表（子串断言），靠通读极难发现。

## 命名与占位

- **文档里不出现项目目录名**：开发机路径写 `<repo>`，生产路径写 `/srv/<deploy-dir>`，systemd 单元 `market-review.service`，nginx 站点 `market-review.conf`。

## 删除文档时的规则

- **已完结且不再被引用的文档 → 直接删除**，靠 git 历史取回，**不留过期横幅**。
- **仍需被引用的历史证据**（可重跑的审计证据脚本）→ 保留，**正文不重写、只加注记**。
- **删任何文件前先跑 `git ls-files --error-unmatch <路径>`**：报错说明它是未跟踪的，删了**永久找不回**，必须先把内容并进别处或单独提交。这条"靠 git 历史取回"的约定**只对已提交的文件成立**。
- **"内容已并入新文件"的验证是逐字包含，不是看行数**：断言"去掉 h1 后的旧正文 `in` 新文件正文"。
- 被删除的文档，**在被引用处留一句出处说明**，不要留下坏链或悬空指路 —— **代码注释与测试 docstring 里的引用也要一起改**。
- 合并**多轮**报告时两轮节号会重复，文内引用必须写成「第 N 轮 §M」。

## 格式与校验

- **架构图用 mermaid 围栏代码块**。语法坑：`subgraph` id 用 ASCII，虚线带标签只能写 `A -. 文本 .-> B`，`participant ... as 名称` 里别放圆括号。
- 改文档后跑本地链接校验（内联 Python 扫 `](...)` 相对路径与同文档锚点），并确认项目目录名残留为 0 命中。
- **成片的 `**` 加粗删除是有意为之**（统一的精修手法），先看同批文件是否同形，**不要当噪声回滚**。
